# BabyLog 自建家庭同步与数据管理说明

## 产品原则

- Android 默认离线可用，不要求注册、登录或填写服务器地址。
- Room 是手机端本地数据的读写入口；同步是用户配置的可选能力。
- NAS 运行独立 Docker 同步服务，不依赖 Supabase 或其他云平台。
- 多台手机使用同一个 BabyLog 账号登录，访问并同步同一份宝宝档案；当前产品不要求家庭成员分别注册独立账号。
- NAS 数据目录是服务端持久化数据的存放位置。升级容器时必须保留数据卷与原有 `BABYLOG_JWT_SECRET`。

## Docker 部署

服务端位于 `server/`，采用 FastAPI、SQLite WAL 和 NAS 文件系统。容器内部监听端口 **18765**，Compose 默认映射主机端口 **18765**。如 NAS 主机端口冲突，只需修改 `BABYLOG_PORT`。

1. 在仓库根目录使用 `docker-compose.yml`（Dockge 可直接导入），复制 `.env.example` 为 `.env`。
2. 设置唯一的随机 `BABYLOG_JWT_SECRET`，至少 32 字符，不能提交到 Git。
3. 将 `BABYLOG_DATA_PATH` 改为 NAS 持久化目录。
4. 在 Dockge 部署 Compose。
5. 建议将专用 HTTPS 域名反向代理到 NAS 的 18765 端口。
6. 执行 `docker compose up -d --build` 启动服务；Dockge 中保存并启动 Compose 项目即可。
7. 检查 `https://你的域名/health` 或 NAS 内网地址的 `/health`。

### HTTPS 反向代理信任配置

如果通过 Lucky、Nginx、Caddy 等反向代理访问 BabyLog，应显式配置 `BABYLOG_TRUSTED_PROXY_IPS`。该变量填写的是**BabyLog 容器实际收到 TCP 连接时看到的代理来源 IP**，不是用户访问的客户端 IP，也不一定是反向代理配置中的上游目标地址。

- 只填写实际代理来源 IP；多个代理可用英文逗号分隔。
- 不要使用 `*`，也不要因为代理上游填写了 NAS 局域网地址，就直接把该地址当作可信代理 IP。
- 可在 NAS 上抓取 BabyLog 监听端口的连接，查看发往 BabyLog 容器 IP 的数据包来源地址；也可结合服务端访问日志核对。
- Docker bridge 网络下，经过宿主机端口转发的连接可能显示为 Docker 网桥网关地址。网络或 Compose 项目重建后，应重新核对该地址是否变化。
- 未配置反向代理时，保留默认值 `127.0.0.1`；不要为了让代理生效而信任整个网段。

示例（仅示意，必须替换成实际抓包确认的地址）：

```dotenv
BABYLOG_TRUSTED_PROXY_IPS=172.23.0.1
```

Compose 已将该变量传递给服务端。若修改 `.env` 或 Dockge 环境变量，需重新创建容器使配置生效。

容器启动时会准备挂载目录权限，随后以 UID/GID 10001 的非 root 用户运行 API。不要暴露数据库文件或 NAS 管理端口。备份数据库时应使用 SQLite 在线备份方式；照片与头像文件也应纳入 NAS 自身的备份策略。

## 账号与多设备

- 每台手机在同步设置中填写相同的 NAS 服务地址。
- 所有需要共享数据的设备使用同一个 BabyLog 账号和密码登录。
- 登录后设备同步同一份宝宝档案与记录，不需要为每位家庭成员分别创建账号。
- Android 本地 Room 数据仍可离线读写；网络不可用时，待同步内容会在网络恢复后继续处理。

## Android 同步范围

宝宝档案以及喂养、辅食、营养补充、护理、睡眠、成长等事件可进行双向同步。辅食（`SOLID_FOOD`）和补充（`SUPPLEMENT`）是独立事件类型，不会并入喂养奶量或喂养次数统计。首次创建家庭时，会将当前手机的宝宝档案和未删除事件加入首次上传队列；其他设备登录同一账号后可拉取已有家庭数据。

成长相册照片支持 NAS 原图上传、跨设备下载和删除墓碑同步；宝宝头像也会独立上传到 NAS，并随宝宝档案变更在设备间下载。头像从 Android 系统照片选择器选取，不依赖文件管理器。

### 相册云端原图与本地存储

- 设置中的“NAS 云端保存原图”是**每台手机独立**的选项，默认关闭；关闭时维持原有本地原图行为。
- 开启后，照片仍先在本机保存原图。只有原图成功上传并收到服务器同步确认后，客户端才会生成 JPEG 轻量预览、更新本地数据库，再释放本机原图。
- 已经同步完成的照片也会在下一次成功同步时逐步转换为轻量预览；尚未上传、待同步、冲突或网络不可用的照片不会释放原图。
- NAS 始终保存原始照片。打开云端原图照片时，App 先显示本地预览，再尝试按需下载原图；离线时仍可查看预览。原图下载缓存上限约 300 MB，按最近使用情况清理。
- 关闭该选项后，后续同步会恢复本机原图保留策略；此前已释放的原图会在联网同步时逐步恢复到本机。此设置不会删除 NAS 原图，也不会改变其他手机的设置。
- 若预览生成失败，客户端保留原图，不会为了节省空间而冒险删除唯一副本。

App 前台运行时会触发家庭同步；后台周期同步由 WorkManager 调度。同步设置页显示待同步数量、冲突数量、最近成功同步时间和最近错误。发生冲突时，客户端保留冲突信息，不应静默覆盖用户数据。

## 网页管理面板

NAS 服务启动后，可通过浏览器访问根路径打开网页面板。网页端使用与 Android App 相同的账号密码登录，网页会话使用安全 Cookie；个人数据 API 需要有效登录状态。

网页面板提供：

- 宝宝档案与记录概览。
- 记录列表分页和日期范围筛选。
- 相册照片浏览。
- 数据备份 ZIP 导出与导入前校验。
- 安全增量导入。

## 备份与恢复

### 导出方式

网页面板默认导出**数据备份**，包括宝宝档案及记录，不包含照片和头像。该方式适合日常定期备份，文件更小，也适合在设备或服务迁移时优先恢复结构化记录。

如需完整迁移相册，在导出时勾选“包含照片和头像”。完整备份会将照片、头像媒体文件一并打包，因此文件可能明显增大。

### 导入规则

1. 在网页面板选择备份 ZIP 并执行“检查备份”。
2. 服务端先将上传内容流式写入临时文件，再校验 ZIP 结构、清单、记录、媒体路径和文件内容。新导出的 v2 备份为每张照片和头像附带 SHA-256 摘要，预检会逐个校验文件摘要；早期 v1 备份仍可导入，但不具备文件级摘要校验。
3. 预览结果会显示备份记录总数、可新增数量、重复/冲突数量和照片数量。
4. 只有在确认预览结果符合预期后，才执行导入。
5. 导入采用增量新增策略：目标端已存在的记录会跳过，不覆盖已有记录，也不会清空目标端数据。
6. 备份包含照片和头像时，才会导入对应媒体文件；纯数据备份不会恢复照片。

**如何理解预览结果：**

- `可新增 76 条`：这些记录当前目标端不存在，确认后会尝试新增。
- `重复/冲突 76 条`：这些记录已经存在，导入时会跳过。
- `可新增 0 条`：目标端已包含备份中的全部记录，通常无需继续导入。

网页 ZIP 上传限制为 **512 MB**。服务端使用流式接收、校验和媒体写入，降低大文件导入的内存占用；仍建议优先使用默认的不含照片数据备份，照片可继续保存在手机相册或通过完整备份另行迁移。

### 安全与数据保护

- 导入前务必先检查备份预览；不要导入来源不明的 ZIP。
- 导入不会覆盖或删除现有记录，但建议在重要迁移前仍保留 NAS 自身的数据库备份。
- 升级容器时保留原有挂载目录，不要删除 `/data`。
- 不要随意更换已部署环境的 `BABYLOG_JWT_SECRET`，否则现有会话令牌会失效。
- 备份文件包含家庭隐私数据，应妥善保存。

## API 与实现约定

Android 同步 API 使用 Bearer Token。网页管理面板使用独立的 Cookie 会话和 CSRF 来源校验；两种认证方式服务于不同入口，不能为了网页端改动而破坏 Android 现有 Bearer Token 接口。

服务端 API 文档端点在生产服务中关闭。具体路由与实现以 `server/app/main.py` 和自动化测试为准。

## 同步协议

每次本地变更生成唯一 operation_id，包含 entity_type、entity_id、operation、payload 和 base_version。服务端以家庭 + operation_id 保证幂等，以记录版本检测并发修改。拉取使用服务端递增 cursor。发生 version_conflict 时客户端保留冲突信息，不静默覆盖。删除通过 delete 操作形成同步墓碑。
