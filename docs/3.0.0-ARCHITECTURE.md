# BabyLog 3.0.0 架构审查与实施基线

## 产品目标

3.0.0 聚焦三项体验升级：图形化日常记录、首页今日照护概览、统一成长时间线。智能助理和社交型相册不纳入本次版本范围。

## 当前架构事实（基于 main 审查）

- Android 使用 Kotlin、Jetpack Compose、Material 3、Room 2.7.1、KSP。
- Room 数据库当前版本为 7，实体包括 `BabyEntity`、`BabyEventEntity`、`BabyPhotoEntity`、`SyncOperationEntity`。
- 日常事件集中存储于 `baby_events`；事件专属数据由 `eventType + payloadJson` 表达。
- 时间线 DAO 已有日期/类型筛选、计数、偏移分页和基于 `occurredAt + id` 的 keyset 分页。
- 首页已有宝宝档案、快捷记录、喂养间隔、当日统计和睡眠计时；睡眠计时状态通过本地 SharedPreferences 持久化。
- 现有五个一级目的地为首页、记录、成长、相册、更多；疫苗记录保持独立入口/独立体验，不并入普通时间线。
- 默认暖色、卡皮巴拉、考拉三套主题继续保留。
- NAS 同步、离线优先、照片路径、备份恢复和同步冲突处理属于必须保持的兼容边界。

## 审查结论

1. 不需要为了 3.0 重建 Room 数据库；在没有明确业务字段缺口前，优先保持数据库版本 7。
2. 不新增平行的“首页事件表”或“时间线事件表”。首页、时间线和统计应复用现有事件数据。
3. 新增统一展示模型属于 UI/domain 层，不是 Room Entity，不写入 payloadJson。
4. `MainActivity` 当前承担应用入口、数据流组合、导航、记录状态和同步交互等多项职责；后续按页面/职责逐步拆分，避免一次性大规模 MVVM 改造。
5. Room 当前声明 `exportSchema = true`，但审查时未找到已提交的 schema 快照，也未发现 KSP 的 `room.schemaLocation` 配置。阶段 0 补齐导出路径，并由 CI 产出 schema artifact；快照在确认生成后再提交。
6. CI 当前包含 Android 单元测试与 APK 构建、NAS API 测试、Docker 构建与健康检查；没有 Android Emulator UI 测试，因此 Compose 视觉、手势和键盘遮挡仍需真机/模拟器验收。

## 不变的数据与行为约束

- 不破坏旧版本 Room 数据库迁移链和历史记录。
- 不重命名或改变既有事件 JSON 字段含义，新增字段必须有默认值/兼容解析策略。
- 保持事件时间排序稳定性：同一时间戳按 ID 决定顺序。
- 首页只查询当日数据；时间线继续分页，禁止为了 UI 一次性加载全部历史。
- 计时中的睡眠与已完成睡眠记录区分，结束保存后才进入正式事件和同步队列。
- 主题偏好仍为本机设置，不进入家庭同步。
- 保持 NAS API、同步队列、照片路径、备份/恢复契约兼容。

## 实施阶段

- 阶段 0：补齐架构约定和 Room Schema 导出基础；确认现有事件/时间线兼容边界。
- 阶段 A：首页重构为今日照护中心，包含概览、进行中状态、图形化快捷记录、今日时间线预览。
- 阶段 B：喂奶、睡眠、尿布、体温和成长测量的图形化记录交互。
- 阶段 C：统一时间线视觉、日期/类别筛选和记录详情。
- 阶段 D：成长趋势和周期统计可视化。
- 阶段 E：三套主题适配、全局精修、数据兼容回归和发布准备。

## 阶段 D：成长趋势与周期统计可视化（交付完成）

### 已交付能力

- **官方成长参考**：按 WS/T 423—2022 提供男女童年龄别体重、身长/身高和头围百分位数据；按实际出生日期计算日历月龄，在官方年龄覆盖范围内插值，不向范围外外推。
- **成长曲线**：实际测量与 P3/P10/P25/P50/P75/P90/P97 参考曲线对照，展示 P3–P97 区间带、辅助线和图例；测量点可选中查看实际数值、日期、月龄及参考区间。
- **成长总览**：体重、身长/身高、头围分别展示最近真实测量、前次测量变化与间隔、最近最多五次测量迷你趋势。
- **百分位历史**：按真实测量日期显示百分位区间散点，并与当前选中的成长测量联动；不连接不同测量点，不补造缺失月份。
- **历史比较**：日期范围过滤不丢失窗口外的前一次真实观测；同时间戳记录保持稳定顺序。
- **周期统计**：日/周/月趋势覆盖喂养、睡眠、护理、补充、辅食、成长、体温和里程碑；区分零值与无记录，显示覆盖天数、有效记录数、非零活动日和日均值；只对完整自然周期进行总量比较。
- **数据边界**：无效值、出生前测量、缺失参考、性别未设置及官方标准年龄上限均有明确处理；身长/身高在24月龄切换官方测量口径。

### 已知限制与使用说明

- 当前宝宝档案没有出生孕周字段，因此暂不计算早产儿矫正月龄。成长界面明确提示标准月龄按出生日期计算，早产儿矫正月龄暂未纳入；不得将当前百分位对照解释为早产儿专属评估。
- 百分位区间仅为同性别、同月龄的标准数据对照，不构成医学诊断或健康结论。
- 成长趋势只展示实际测量；缺少测量的日期/月龄不会被插值为宝宝的观测值。
- 周期统计中的缺失日期按零值展示时，会同时保留有效记录数，避免把“无记录”误读为“有记录但数值为零”。

### 阶段 D 验收结果

- 成长参考数据、插值边界、测量排序、百分位分类、区间历史、周期聚合和周期比较均有 Android 单元测试覆盖。
- 阶段 D 最近交付 PR：#279 成长总览、#280 迷你趋势、#281 日期范围历史比较、#282 百分位区间历史。
- #282 已合并；Android APK/单元测试、NAS API 测试和 NAS Docker 构建/健康检查均通过。
- 未修改 Room schema、事件 payload、NAS 同步协议或备份格式。

**阶段 D 状态：完成。** 下一阶段为阶段 E：主题适配、全局体验精修、数据兼容回归与发布准备；阶段 E 不代表自动发布版本或部署 NAS。

## 验收原则

每个独立改造项先跑对应 Android 单元测试；涉及数据结构时增加迁移/兼容测试；每阶段结束跑完整 Android、NAS API 和 Docker CI。阶段 0 和阶段 A 不发布正式版本，也不更新 NAS 容器。
