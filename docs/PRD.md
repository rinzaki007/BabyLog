# BabyLog 产品需求与范围

## 产品定位

BabyLog 是一款离线优先的宝宝照护记录、成长档案与家庭数据管理应用。核心目标是让家庭能够长期、准确、可追溯地记录宝宝成长，并由自己掌握数据。

手机端无需注册、联网或配置服务器即可独立使用。需要多设备共享、远程查看或集中备份时，可选连接家庭自行部署的 NAS 同步服务。BabyLog 不依赖 Supabase 或其他托管云平台。

## 核心原则

- **离线优先**：所有日常记录先保存到 Android 本地 Room 数据库；网络中断不阻止记录。
- **用户掌握数据**：本地数据由用户设备保存；可选 NAS 服务由用户自行部署和维护。
- **同步可选且可恢复**：未配置 NAS 时不发起同步请求；配置后通过待处理队列同步，网络恢复后继续处理。
- **不静默丢失数据**：同步冲突应保留在本机并展示原因，用户可检查、恢复或重新提交；不自动覆盖用户记录。
- **长期可追溯**：时间线、测量趋势、成长回顾与报告基于真实保存的数据，不插值、不推测。
- **隐私优先**：不公开分享宝宝档案，不收集不必要的家庭信息，不将真实家庭数据写入仓库或测试样例。
- **不做医疗诊断**：疫苗安排和健康记录用于信息整理与提醒，不替代医生建议、诊断或专业医疗服务。

## 当前产品范围

### 宝宝档案与日常记录

- 宝宝档案与基础资料。
- 喂养记录：亲喂、瓶喂及相关喂养信息。
- 日常护理：小便、大便及可选观察信息。
- 辅食与营养补充记录，支持自定义项目。
- 睡眠记录与作息回顾。
- 成长测量：体重、身长、头围等真实测量数据。
- 统一时间线：按发生时间查看、补录、编辑和软删除记录。

### 成长、相册与家庭回顾

- 成长里程碑、成长时间线和阶段回顾。
- 成长报告导出，便于家庭长期保存和分享。
- 成长相册：时间线浏览、照片详情与沉浸式查看。
- 可选 NAS 原图保存、跨设备照片下载和本地原图恢复。
- 家庭纪念日与生日提醒，支持长期持续生成，不依赖固定的短期年龄上限。

### 疫苗计划

- 查看疫苗接种安排并记录完成情况。
- 区分明确待接种、逾期、近期安排与需要门诊核对的项目。
- 对联合疫苗或需要专业确认的计划单独标记，不将其错误归类为逾期。
- 不提供医疗诊断、剂量判断或替代专业人员的接种建议。

### 家庭同步与 NAS 管理

- 用户可选部署 FastAPI + SQLite NAS 同步服务。
- 多台设备使用同一个 BabyLog 账号登录，共享同一家庭数据空间；当前版本不提供每位家庭成员独立账号与权限体系。
- Android 端使用 Bearer Token；网页管理面板使用独立的安全 Cookie 会话与 CSRF 来源校验。
- 本地变更进入同步队列，服务端通过 operation ID 幂等处理、版本检测与递增游标拉取数据。
- 冲突记录保留在本机，显示待处理数量、错误信息与最近成功同步状态；支持检查和分批查看冲突详情。
- 相册照片与头像支持按需同步，原图释放前必须确认云端已保存；失败时保留本机原图。
- NAS 网页面板提供记录查看、照片浏览和数据管理入口。

### 备份与恢复

- 默认数据备份包含档案和记录，不强制打包照片。
- 用户可主动选择包含照片和头像的完整媒体备份。
- 导入前先校验归档结构、清单、路径与媒体完整性。
- 采用增量新增原则：已存在的记录跳过，不覆盖、不清空目标端数据。
- 备份文件包含家庭隐私数据，用户需自行妥善保管。

### 应用更新

- 提供 GitHub 正式 Release 更新源。
- 用户可选使用 NAS 缓存的 APK 更新镜像。
- 安装前校验文件大小与 SHA-256，最终由 Android 系统安装器校验签名并请求用户确认。

## 技术架构与数据边界

| 部分 | 当前实现 |
| --- | --- |
| Android 客户端 | Kotlin、Jetpack Compose、Room、WorkManager |
| 本地数据 | Room 数据库；离线记录优先写入本机 |
| NAS 同步服务 | Python、FastAPI、SQLite WAL |
| NAS 网页管理 | 服务端静态页面、Cookie 会话与 CSRF 校验 |
| 部署 | Docker Compose / Dockge，数据持久化到用户指定目录 |
| CI | Android 单元测试与 debug APK、NAS API 测试、NAS Docker 构建与 smoke test |
| 正式发布 | 独立 GitHub Actions 签名 APK Release 工作流 |

### 数据与兼容性约束

- 修改 Room Entity、DAO 或数据库结构时，必须提供可验证的迁移，并保留既有档案、记录和媒体引用。
- 修改同步 payload、operation 类型或 API 行为时，必须同步更新 Android、NAS 服务端、契约文档和测试。
- Android Bearer Token API 与网页 Cookie 会话是不同入口，不得为网页功能破坏现有 Android 同步兼容性。
- 同步删除通过墓碑传播；冲突不能静默覆盖用户数据。
- 照片原图只有在上传确认成功后才能释放；预览生成、上传或下载失败时保留可恢复的数据。
- NAS 容器升级必须保留 /data 持久化卷和既有 BABYLOG_JWT_SECRET。
- 备份导入必须限制归档大小、条目数量、解压体积和媒体路径，并采用流式处理避免将整个归档载入内存。
- CI debug APK 不是正式发布包；正式 APK 必须使用长期保存的签名密钥，并核验 Release 与公开更新清单。

## 明确不在当前范围内

- 医疗诊断、自动开药或替代医生的接种决策。
- 公开分享宝宝档案、社交动态、社区或广告。
- 强制用户注册、强制连接第三方云平台或依赖托管 SaaS。
- 每位家庭成员独立账号、细粒度角色权限与复杂家庭组织体系。
- 自动清除同步冲突、自动覆盖远端记录或未经确认删除用户数据。
- 为增加功能数量而引入没有明确长期维护价值的复杂系统。

## 维护方向

后续迭代优先级依次为：

1. 数据安全、备份恢复和同步正确性。
2. 长期使用边界：跨年龄提醒、历史记录、照片原图与离线恢复。
3. 记录效率、移动端可用性和界面一致性。
4. CI、发布流程、依赖维护和文档准确性。

新增功能应能说明它解决的真实使用问题，并评估本地数据、同步协议、NAS 部署和长期兼容性的影响。若没有明确收益，优先保持现有实现简单、稳定、可维护。
