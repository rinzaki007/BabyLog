# BabyLog 3.0.0 阶段 E：兼容性与发布准备审查

## 审查结论

阶段 E 的代码与测试审查未发现需要升级 Room schema、重写历史事件 payload 或调整 NAS 同步/备份协议的必要缺口。当前数据边界保持：

- Room 数据库版本为 **7**，已提交快照：`app/schemas/com.rinzaki.babylog.data.BabyLogDatabase/7.json`。
- 日常事件继续由 `eventType + payloadJson` 表达；本轮未改变已有 JSON 字段含义。
- 本地数据库和同步操作队列仍是记录主路径；NAS 同步是可选能力。
- 云端照片存储默认关闭，设备级偏好不进入家庭同步。
- 备份与恢复继续由 NAS 网页管理面板提供；Android 应用没有另行实现本地 ZIP 备份/恢复入口。
- 本轮不升级版本、不发布 APK、不部署 NAS。

## 当前 CI 验收范围

工作流 `.github/workflows/android.yml` 包含三条必需检查：

1. **Android APK**：运行 `testDebugUnitTest`，构建 Debug APK，检查启动器图标和主题插画资源，并上传 Room schema 与 APK artifact。
2. **NAS Sync API tests**：运行 `server/tests` pytest 测试集。
3. **NAS Docker image**：构建镜像、以只读文件系统和受限权限启动容器、检查健康端点，并校验 Compose 配置。

CI 当前没有 Android Emulator / Compose UI 自动化测试。因此，自动化全绿能够证明编译、单元测试、API 测试和容器构建通过，但不能代替真机对动画、手势、键盘遮挡、TalkBack 实际播报和不同系统字体缩放的验收。

## 真机验收清单

发布前仍建议在至少一台常规尺寸 Android 设备和一台窄屏/大字体环境检查：

- [ ] 默认、卡皮巴拉、考拉主题下：首页、记录、成长、相册、疫苗、设置的颜色、插画和文字层级一致。
- [ ] 底部五个入口切换、横向滑动、系统返回和设置弹窗关闭行为正常；疫苗仍为独立入口。
- [ ] 首页摘要、同步状态、快捷记录的 TalkBack 名称不重复，展开/收起状态可感知。
- [ ] 记录表单在窄屏和输入法弹出时，主要字段与保存操作可见、可触达。
- [ ] 相册双列布局、照片查看器缩放/翻页、原图按需加载和来源状态展示正常。
- [ ] 成长图表在窄屏下图例、坐标轴、选中点详情和日期范围切换可用。
- [ ] 断网时可以正常查看和新增本地记录；恢复网络后同步队列可继续完成。
- [ ] 两台设备登录同一账户后，新增/删除记录与照片状态一致；冲突不会静默覆盖本地新记录。
- [ ] NAS 网页端分别验证无照片备份与含照片备份的导出、预览、导入恢复；先使用测试账户/数据验证。

## 阶段 E 边界与完成条件

- 本审查没有理由改变 Room v7、事件 payload、NAS API、同步队列格式或备份格式。
- NAS 备份/恢复的自动化证据来自服务器测试；不能把它描述为 Android 本地备份功能。
- 真机清单是发布前人工验收项，不能仅凭 CI 通过标记为已完成。
- 阶段 E 的自动化兼容性审查可在三项 CI 全绿后关闭；正式发布仍需完成真机验收，并由用户明确决定。

**阶段 E 状态：自动化兼容性审查完成；真机发布前验收待执行。**
